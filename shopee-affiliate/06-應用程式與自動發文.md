# 蝦皮分潤助手 — 應用程式與自動發文

手機、電腦都能開的網頁應用，不用裝 App Store 的東西。資料存在你的裝置，想跨裝置就同步到 GitHub；同一份資料也是 Threads 自動發文機器人的排程表。

## 1. 打開應用

| 方式 | 網址 / 做法 |
|------|------------|
| 線上版（推薦） | https://isaacmolt.github.io/-/shopee-affiliate/app/ （這個分支推上去後 GitHub Pages 會自動部署，約 1-2 分鐘） |
| 加到手機主畫面 | iPhone：Safari 開網址 → 分享 → 加入主畫面。Android：Chrome 開網址 → 右上選單 → 安裝應用程式 |
| 電腦 | 任何瀏覽器開同一個網址；Chrome 網址列右邊有「安裝」圖示可以裝成視窗 |
| 本機 | 在 repo 目錄跑 `python -m http.server 8765 -d shopee-affiliate/app`，開 http://127.0.0.1:8765 |

第一次打開會載入 repo 的 `shopee-affiliate/app/data.json`（裡面是 12 個範例商品與 90 篇範例排程）。之後所有修改都存在這台裝置的瀏覽器裡，離線也能開。

## 2. 五個分頁

| 分頁 | 做什麼 |
|------|--------|
| 今日 | 今天要發的貼文。每張卡：複製文案、複製連結、**開 Threads 發文**（會把文案帶進 Threads 的發文框）、分享到任何 App、標記已發佈、跳過、編輯 |
| 選品 | 商品庫。新增 / 編輯 / 刪除，填分潤短連結，看每單約賺多少，一鍵產生貼文 |
| 貼文 | 選商品 + 平台 + 類型 → 自動套模板 → 改口氣 → 加入排程。「自動排程」一鍵排 N 天。下面是所有排程，可篩待發 / 已發 / 失敗 |
| 數據 | 每天把後台的點擊 / 訂單 / 分潤填進來。本月 KPI、轉換率、每單分潤、目標進度、提領門檻與 5 萬警示 |
| 設定 | 帳號與揭露文字、連結放哪裡、自動發文開關、各平台時段、目標、GitHub 同步、匯出 / 匯入 |

手機上「開 Threads 發文」會跳到 Threads 並把文案填好，你只要按發佈，再把連結貼到第一則留言。這是不用 API 的半自動發文，今天就能用。

## 3. 手機和電腦用同一份資料（GitHub 同步）

1. GitHub 右上頭像 → **Settings** → 最下面 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. Repository access 選 **Only select repositories** → 選這個 repo
3. Permissions → Repository permissions → **Contents** 選 **Read and write**（只要這一個）
4. Expiration 選 1 年，Generate，複製 token（只會顯示一次）
5. 打開應用 → 設定 → GitHub 同步：填 owner（`Isaacmolt`）、repo（`-`）、branch（目前是 `claude/shopee-commission-planning-isbmsh`）、token → **測試連線** → **推送**
6. 另一台裝置做同樣設定 → **拉取**。打開「改了就自動推送」之後，每次修改 4 秒後自動推上去；每次打開應用會自動拉取

token 只存在該裝置的瀏覽器，不會寫進 data.json，也不會被 commit。若裝置遺失，到 GitHub 把 token 撤銷即可。

同步規則：以你這台裝置為準，但機器人寫回的「已發佈 / 失敗」狀態一定會被合併進來，不會被你的舊資料蓋掉。

## 4. Threads 自動發文

### 運作方式

```
應用「貼文」頁排程 ──推送──▶ repo 的 data.json
                                   │
                  GitHub Actions 每小時 05 分 ──▶ scripts/threads_autopost.py
                                   │   時間到了、auto=true 的 Threads 貼文 → Threads API 發佈
                                   │   連結模式 reply：主文發完，自動回一則留言放分潤連結
                                   ▼
                          結果（posted / error）寫回 data.json ──拉取──▶ 應用「今日」顯示 ✅
```

### 設定步驟（一次，約 30 分鐘）

1. **Threads 開發者設定**
   - 到 https://developers.facebook.com/ 用 Facebook 帳號登入 → My Apps → **Create App**
   - Use case 選 **Access the Threads API**，建立 App
   - 左邊 **Use cases → Threads API → Settings**，加入你的 Threads 帳號為 **Threads Tester**
   - 用手機打開 Threads → 設定 → 帳號 → **網站權限 → 邀請**，接受邀請
   - 回到開發者後台，在 **User Token Generator** 對你的帳號按 **Generate Access Token**，複製（這是 60 天長效 token）
   - 介面常改，以官方文件為準：https://developers.facebook.com/docs/threads
2. **放進 GitHub Secrets**
   - repo → **Settings → Secrets and variables → Actions → New repository secret**
   - `THREADS_ACCESS_TOKEN` = 剛剛的 token
   - `THREADS_USER_ID` 可不填，機器人會自己查
3. **應用設定 → 打開「Threads 自動發文」→ 儲存 → 推送**
4. **先測一次**：repo → Actions → 「Threads 自動發文」→ Run workflow → `dry_run` 打勾 → 看 log 列出會發什麼，確定沒問題再跑一次不打勾
5. 每小時 05 分自動跑。只發「時間已到、狀態待發、auto 打開」的 Threads 貼文，一次最多 5 篇

### 重要限制

| 項目 | 說明 |
|------|------|
| 排程只在預設分支跑 | GitHub 的 cron 只看預設分支（目前是 `claude/ai-ceo-business-ops-LKFzy`）。合併前只能手動 Run workflow。或在 repo **Settings → Secrets and variables → Actions → Variables** 新增 `AUTOPOST_BRANCH` 指定要讀寫的分支 |
| token 60 天到期 | 工作流程每週一會嘗試自動換新，但需要再加一個 Secret `GH_PAT`（有 Secrets 寫入權的 classic token）。沒設就每 50 天手動重新產生一次 |
| 500 字 | 超過會標記失敗，不會發 |
| 每天 250 篇 | Threads API 上限，正常用不會碰到 |
| 圖片 | 目前只發文字。要帶圖需要公開的圖片網址，之後可以接 GitHub Pages 上的商品圖 |
| 範例資料 | **把範例商品換成真的之前，不要打開自動發文**，不然會把佔位文案發出去 |

### 連結放哪裡（設定 → 連結放哪裡）

- **第一則留言**（預設）：主文乾淨不被壓觸及，機器人發完主文自動回一則「🔗 連結」留言
- **連結卡片**：用 Threads 的 `link_attachment`，主文下面會有預覽卡
- **文末**：直接接在文案後面

## 5. 還是要手動的事

| 事項 | 原因 | 怎麼做最快 |
|------|------|-----------|
| 產生蝦皮分潤短連結 | 蝦皮沒有公開 API | 後台「商品連結產生器」貼網址 + sub_id，20 秒一個；填回應用的選品 |
| Instagram 發文 | 需要企業帳號 + 圖片才能用 API | 今日頁「複製文案」→ IG 貼；下一版可接 Graph API |
| 蝦皮影音上傳 | 只能在蝦皮 App 內 | 用「貼文」頁的分鏡腳本拍，App 內上傳掛商品 |
| 後台數據 | 沒有 API | 每天晚上在「數據」頁填 5 個數字，1 分鐘 |
